# Django CRM для йога-студии

**Статус:** Активная разработка  
**Стек:** Django (Python), SQLite, HTML/CSS, Vanilla JS, FullCalendar.js v6

---

## 📋 Описание проекта

CRM-система для управления йога-студией с полным циклом: от расписания занятий и управления залами до учёта посещаемости, финансов и личного кабинета ученика.

---

## 🗂 Модели данных (`core/models.py`)

| Модель | Описание |
|--------|----------|
| `Tariff` | Тарифы для занятий (групповые, индивидуальные, сплит). Поля: название, тип тарифа, цена за человека, полная цена за сплит, макс. участников, описание, статус активности. **Поддержка абонементов**: флаг доступности, количество занятий, стоимость, срок действия |
| `Subscription` | Абонементы клиентов. Поля: клиент, тариф, количество занятий (всего/осталось), дата активации, дата истечения, статус (active/expired/used_up/cancelled). Активируется при первом использовании, сгорает через заданный период |
| `User` | Пользователи и клиенты студии в одной модели (наследуется от `AbstractUser`). Поля: username (логин), телефон, имя, фамилия, роль (ученик/модератор/администратор), статус активности, баланс, **allowed_tariffs** (M2M связь с тарифами) |
| `Hall` | Залы с полем `color` (10 цветовых вариантов) |
| `ClassType` | Типы занятий (название, описание, длительность, **default_tariff**) |
| `ClassSession` | Расписание занятий с поддержкой повторяющихся событий. **Поле tariff** (связь с тарифом) |
| `Booking` | Записи пользователей на занятия. Поля: сессия, клиент, статус (pending/confirmed/paid/cancelled), дата записи, дедлайн оплаты (за 4 часа), дата оплаты, сумма оплаты, **is_subscription_used** (оплачено абонементом), **subscription** (ссылка на абонемент) |
| `PaymentTransaction` | Детализированная история финансовых операций. Поля: клиент, тип операции (deposit/debit/refund/adjustment/subscription_purchase), сумма, баланс до/после, связь с записью или абонементом |
| `Attendance` | Посещаемость (клиент + занятие + статус) - используется для статистики после занятия |
| `Payment` | Оплата клиентами (разовое/абонемент/пакет) - для прямого пополнения баланса |
| `RentPayment` | Оплата аренды залов |

## ✨ Ключевой функционал

### Система тарифов
- **Типы тарифов:** групповой, индивидуальный, сплит
- **Гибкое ценообразование:** поддержка разных моделей оплаты
- **Умное ценообразование для сплита:** если в сплит-группу записался один человек — он платит полную стоимость за двоих
- **Фильтрация занятий:** пользователи видят только занятия, доступные по их тарифам

### Система абонементов
- Покупка пакета занятий (например, 8 занятий за 9000₽) со сроком действия (45 дней)
- Активация при первом посещении, автоматический расчет даты истечения
- Сгорание неиспользованных занятий по истечении срока
- Поддержка не для всех тарифов (настраивается в админке)
- Автоматическое использование абонемента при записи на подходящие занятия

### Ролевая модель и права доступа
- **Ученик:** просмотр расписания, запись на занятия, отмена записи (не позднее чем за 4 часа до начала); использует кастомные страницы входа и профиля; получает права по умолчанию из настроек системы
- **Модератор:** полный доступ к управлению расписанием (назначается администратором); использует стандартный интерфейс админ-панели; права наследуются от групп
- **Администратор:** полный доступ ко всем функциям системы, включая назначение модераторов и настройку прав по умолчанию; использует стандартный интерфейс админ-панели
- **Суперадмин:** полный доступ ко всем функциям системы; использует стандартный интерфейс админ-панели
- **Группы прав:** гибкая система назначения прав через группы; при добавлении пользователя в группу ему автоматически присваиваются её права; изменения прав группы синхронизируются со всеми участниками

### Автоматизация
- **Повторяющиеся события:** при создании занятия с флагом `is_recurring` автоматически генерируется серия на 4 недели вперёд
- **Автоматическое списание:** списание средств за 4 часа до занятия через сервис платежей
- **Детализация финансовых операций:** каждая транзакция записывается с балансом до и после операции

### Дополнительные возможности
- **Цветовая кодировка:** цвет события в календаре зависит от цвета выбранного зала
- **Локальное время:** корректная обработка времени без UTC-сдвигов (диапазон 08:00–20:00)

## 🔐 Система аутентификации

### Регистрация и вход
- Регистрация по номеру телефона (используется как логин)
- Маска ввода телефона с автоматическим форматированием (+7 (XXX) XXX-XX-XX)
- Валидация номера телефона
- Автозаполнение паролей браузером (поддержка генерации надежного пароля)

### Авторизация через Telegram
- **Telegram Login Widget:** современный виджет для быстрого входа через Telegram
- **Автоматическая регистрация:** при первом входе создаётся новый пользователь с привязкой к `telegram_id`
- **Безопасность:** криптографическая проверка подписи данных (HMAC-SHA256), валидация актуальности данных (24 часа)
- **Уведомления:** после авторизации система может отправлять уведомления через Telegram (напоминания о занятиях, акции, изменения в расписании)
- **Настройка:** подробная инструкция в файле `TELEGRAM_AUTH_SETUP.md`

### Страницы аутентификации
- **Кастомная страница входа (`/login/`):**
  - Современный дизайн с градиентным фоном
  - Центрированная форма входа
  - Ссылка на регистрацию
  - Кнопка «Вход для администратора» → перенаправляет на `/admin/login/`
  - Доступна только для обычных пользователей (учеников)
  - Администраторы, модераторы и суперадмины перенаправляются на стандартную страницу входа админ-панели (`/admin/login/`)
  
- **Кастомная страница регистрации (`/register/`):**
  - Регистрация по номеру телефона с маской ввода
  - Валидация номера телефона
  - Современный дизайн с градиентным фоном

- **Кастомная страница профиля (`/profile/`):**
  - Отображение личной информации пользователя
  - История посещений занятий
  - Информация об активных абонементах (остаток занятий, срок действия, статус)
  - Динамическое приветствие: «Доброе утро/день/вечер %имя%» в зависимости от времени суток
  - Боковое меню: отображается только для модераторов, администраторов и суперадминов
  - Для обычных пользователей — упрощённый интерфейс без бокового меню
  - Кнопка "Перейти к расписанию" в блоке balance-info

### 🔧 Технические детали кастомного виджета прав доступа
**Причина замены:** Стандартный интерфейс Django (`filter_horizontal` / `filter_vertical`) неудобен при большом количестве прав — требует двойного клика для переноса между списками, не даёт общей картины.

**Реализация:**
- **Файл виджета:** `core/widgets.py` — класс `CustomPermissionWidget`, наследуется от `widgets.CheckboxSelectMultiple`
- **Шаблон виджета:** `core/templates/core/admin/widgets/permission_table.html` — отображает права в виде таблицы
- **Структура таблицы:**
  - Первый столбец: название модели (например, «Запись на занятие»)
  - Последующие столбцы: чекбоксы для прав Add, Change, Delete, View
  - Группировка по моделям (content_type)
  - Всплывающие подсказки (tooltip) при наведении на строку с подробным описанием назначения прав
- **Стили:** `core/static/core/css/admin_permissions.css` — оформление таблицы, hover-эффекты (цвет #161616), позиционирование подсказок
- **Интеграция:** Подключён в `core/admin.py` через `formfield_for_manytomany` для поля `user_permissions` моделей User и Group
- **Локализация:** Русские названия моделей и прав через `verbose_name` и `_meta` моделей Django

**Принцип работы:**
1. Виджет получает queryset всех прав (`Permission.objects.all()`)
2. Группирует права по `content_type` (модели)
3. Для каждой модели создаёт строку таблицы с чекбоксами для каждого типа права (add, change, delete, view)
4. При сохранении формы выбранные чекбоксы преобразуются обратно в queryset прав
5. Изменения сохраняются в базу данных через стандартный механизм Django

**Преимущества:**
- Наглядность: все права одной модели в одной строке
- Скорость работы: один клик для активации права
- Понятность: всплывающие подсказки объясняют назначение каждой группы прав
- Масштабируемость: автоматически адаптируется при добавлении новых моделей

## 📅 Модуль: Календарь расписания (FullCalendar)

### 🎯 Назначение
Центральный интерфейс для просмотра, создания и управления расписанием занятий йога-студии. Обеспечивает визуализацию занятости залов и управление событиями в реальном времени с учётом ролей пользователей.

### 🛠 Технологический стек
- **Библиотека:** FullCalendar.js v6 (чистый JS)
- **Backend:** Django Views + JSON API
- **Стили:** `calendar.css`
- **Логика:** `calendar.js`
- **Шаблон:** `calendar.html`

### ✨ Ключевые функции

#### 1. Визуализация событий
- **Цветовая кодировка:** Цвет события соответствует цвету зала
- **Формат отображения:** Время, название занятия и зала (например: `10:00 Растяжка | Дом йоги`)
- **Режимы просмотра:** Месяц, Неделя, День, Список
- **Навигация:** Кнопки «Сегодня», «Назад», «Вперед»

#### 2. Управление событиями (CRUD) - только для администраторов и модераторов
- **Создание:** Через модальное окно с выбором типа занятия, зала, времени начала и максимальной вместимости
- **Редактирование:** Двойной клик по событию
- **Drag-and-Drop:** Перетаскивание и изменение длительности
- **Удаление:** С выбором варианта для повторяющихся событий («Удалить только это» или «Удалить это и последующие»)
- **Выбор времени начала:** Два выпадающих списка — часы (08–20) и минуты (00–50 с шагом 10) 
- **Генерация серий:** На 4 недели вперед при повторении
- **Настройка максимальной вместимости:** Ряд из 9 кнопок (от 2 до 10 мест) и поле ввода для произвольного значения, равномерно распределённые по ширине блока в одну строку; визуальная подсветка выбранной кнопки

#### 3. Запись на занятия и посещаемость
- **Модальное окно с вкладками:** При клике на событие открываются вкладки в зависимости от роли пользователя:
  - **Для учеников:** Только вкладка **«Запись»** с заголовком «Запись на занятие»
    - Список уже записанных на занятие учеников
    - Отображение количества свободных мест
    - Кнопка «Записаться на занятие» (при наличии мест и более чем за 4 часа до начала)
    - Кнопка «Отменить запись» (если пользователь записан и более чем за 4 часа до начала)
  - **Для администраторов и модераторов:** Две вкладки:
    - **«Редактирование»:** Изменение параметров занятия (тип, зал, время, описание, максимальная вместимость)
    - **«Запись»:** Управление списком участников
      - Чекбоксы для отметки фактического посещения
      - Ручное добавление клиентов через поиск по имени/телефону
      - Кнопка «Сохранить» для обновления списка посещаемости
      - Учёт посещения для последующего списания средств с баланса

#### 4. Навигация и доступ
- **Кастомное боковое меню:** Доступно на всех страницах календаря и в личном кабинете ученика
- **Ролевой доступ:** Автоматическое перенаправление пользователей в зависимости от роли (ученики → кастомные страницы, персонал → админ-панель)

## 💰 Система оплаты и списаний

### Архитектура
Система оплаты построена вокруг ключевых моделей:
1. **Tariff** — определяет стоимость занятий разных типов, параметры абонементов
2. **Subscription** — абонементы клиентов (количество занятий, срок действия, статус)
3. **Booking** — фиксирует запись пользователя на занятие, поддерживает оплату абонементом
4. **PaymentTransaction** — детализирует каждую финансовую операцию, включая покупку абонементов

### Процесс списания средств (разовые занятия)
1. Пользователь записывается на занятие → создается запись со статусом `confirmed`
2. Автоматически устанавливается дедлайн оплаты (за 4 часа до начала занятия)
3. **Сервис PaymentService.process_payment_deadlines()** проверяет записи с наступившим дедлайном
4. При наступлении дедлайна происходит списание средств с баланса пользователя
5. Создается транзакция с типом `debit` с указанием баланса до и после операции
6. Статус записи меняется на `paid`

### Процесс работы с абонементами
1. **Покупка:** пользователь покупает абонемент через баланс (списывается полная сумма, создается модель `Subscription` со статусом `active`)
2. **Активация:** абонемент активируется автоматически при первом использовании (первой записи на занятие)
3. **Использование:** при записи на занятие система проверяет наличие действующего абонемента для данного тарифа
   - Если абонемент действителен → занятие оплачивается из абонемента (списывается 1 сеанс)
   - Если абонемент истек или закончился → используется обычный способ оплаты (списание с баланса)
4. **Сгорание:** через заданный период (например, 45 дней) после активации абонемент автоматически переходит в статус `expired`, неиспользованные занятия сгорают

### Тарифы
| Тип тарифа | Описание | Ценообразование | Абонемент |
|------------|----------|-----------------|-----------|
| **Групповой** | Занятия в группе до 10 человек | Фиксированная цена за человека | ✅ Доступен (8 занятий за 9000₽, 45 дней) |
| **Индивидуальный** | Персональная тренировка | Повышенная цена за персональный фокус тренера | ❌ Не доступен |
| **Сплит** | Занятие для пары (2 человека) | Цена за человека × 2 (полная стоимость за обоих) | ❌ Не доступен |

### Финансовые операции
Все операции детализируются в модели `PaymentTransaction`:
- **Типы операций:** `deposit` (пополнение), `debit` (списание), `refund` (возврат), `adjustment` (корректировка), `subscription_purchase` (покупка абонемента)
- **Прозрачность:** каждая операция хранит баланс до и после изменения
- **Аудит:** полная история всех движений средств по каждому клиенту

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Настройка переменных окружения
Создайте файл `.env` в корне проекта на основе `.env.example`:
```bash
# Django settings
DJANGO_SECRET_KEY=your-secret-key-here
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

# Telegram Bot Token
TELEGRAM_BOT_TOKEN=your_bot_token_here
```

**Важно:** Файл `.env` не должен попадать в репозиторий! Для локальной разработки и продакшена создавайте разные версии этого файла с соответствующими настройками (`DEBUG=False`, правильные домены в `ALLOWED_HOSTS` и т.д.).

```bash
python manage.py migrate
```

## 📋 Описание прав доступа

Система прав доступа основана на группах и индивидуальных правах. Все права сгруппированы по моделям:

| Модель | Права | Описание |
|--------|-------|----------|
| **Администрирование** | Запись в журнале (view/change/delete) | Просмотр и управление журналом действий пользователей |
| **Пользователи и группы** | Группа (add/change/delete/view) | Управление группами прав доступа |
| | Право (add/change/delete/view) | Прямое управление отдельными правами (для разработчиков) |
| | Тип содержимого (add/change/delete/view) | Технические права для работы системы |
| **Core** | Посещение (add/change/delete) | Отметка фактического посещения занятий |
| | Запись на занятие (add/change/delete) | Управление записями клиентов на занятия |
| | Занятие (add/change/delete) | Создание и редактирование расписания занятий |
| | Тип занятия (add/change/delete) | Управление видами практик (Хатха-йога, Виньяса и т.д.) |
| | Зал (add/change/delete) | Добавление и настройка залов студии |
| | Оплата (add/change/delete) | Управление платежами клиентов |
| | Финансовая операция (add/change/delete) | Учёт всех финансовых транзакций |
| | Оплата аренды (add/change/delete) | Платежи за аренду залов |
| | Абонемент (add/change/delete) | Выдача и управление абонементами клиентов |
| | Тариф (add/change/delete) | Настройка тарифных планов системы |
| | Клиент (add/change/delete) | Управление карточками клиентов |
| | Настройки новых пользователей (add/change/delete) | Конфигурация прав и тарифов по умолчанию |
| **Сессии** | Сессия (add/change/delete/view) | Управление активными сессиями пользователей |

### Различие похожих прав:
- **Занятие** vs **Тип занятия**: Занятие — конкретный урок во времени, Тип занятия — вид практики
- **Запись на занятие** vs **Посещение**: Запись — бронирование места, Посещение — фактическое присутствие
- **Оплата** vs **Финансовая операция**: Оплата — платеж клиента, Фин. операция — любая проводка в системе
- **Абонемент** vs **Тариф**: Абонемент — продукт для клиента, Тариф — уровень доступа к системе

## 🔐 Безопасность

- Все пароли хешируются стандартными средствами Django
- CSRF-защита на всех формах
- Проверка прав доступа на уровне представлений
- Криптографическая проверка данных Telegram (HMAC-SHA256)
- Валидация актуальности данных авторизации (24 часа)
- Изоляция данных пользователей по ролям
- **Разделение конфигураций:** чувствительные настройки (SECRET_KEY, DEBUG, ALLOWED_HOSTS, ключи API) вынесены в `.env` файл, который не попадает в репозиторий
