# Поэтапный план разработки CRM для йога-студии

## Общие принципы
- Каждый этап завершается рабочим функционалом, доступным для локального тестирования
- Локальный запуск через Docker Compose (PostgreSQL, Redis) + локальные серверы бэкенда и фронтенда
- Доступ к приложению через браузер по адресу `http://localhost:3000` (фронтенд) и `http://localhost:5000/api` (бэкенд API)
- Все изменения версионируются в Git с понятными коммитами

---

## Этап 1: Инициализация проекта и базовая инфраструктура
**Цель:** Настроить окружение, базу данных и базовую структуру проекта.

### Задачи:
1. Инициализация Git-репозитория и структуры папок
2. Настройка Docker Compose (PostgreSQL 15+, Redis 7+)
3. Создание NestJS-проекта для бэкенда
4. Настройка Prisma ORM и схемы базы данных (11 сущностей из ТЗ)
5. Создание первых миграций БД
6. Настройка переменных окружения (.env)
7. Базовый health-check эндпоинт

### Результат:
- Рабочее локальное окружение
- Подключенная БД с начальной схемой
- Запускающийся бэкенд с проверкой здоровья

---

## Этап 2: Аутентификация и ролевая модель
**Цель:** Реализовать систему входа и разграничение прав доступа.

### Задачи:
1. Регистрация/авторизация через Email + пароль
2. Интеграция Telegram Login Widget
3. Интеграция VK OAuth
4. JWT-токены и refresh-токены
5. Ролевая модель (Администратор, Менеджер, Тренер, Клиент)
6. CRUD профиля пользователя
7. Middleware для защиты роутов

### Результат:
- Работающая регистрация и вход всеми способами
- Разделение прав доступа
- Личный кабинет пользователя (базовый)

---

## Этап 3: Управление контентом и расписанием
**Цель:** Создать админ-панель для управления направлениями, абонементами и расписанием.

### Задачи:
1. CRUD направлений йоги
2. CRUD абонементов (типы, цены, сроки, заморозки)
3. CRUD расписания занятий
4. Интеграция FullCalendar v6 с drag-and-drop
5. Админ-панель на React + Tailwind CSS
6. Валидация данных через Zod
7. API документация Swagger

### Результат:
- Полноценная админ-панель
- Интерактивный календарь расписания
- Управление направлениями и абонементами

---

## Этап 4: Запись на занятия и работа с клиентами
**Цель:** Реализовать основной функционал записи и личного кабинета клиента.

### Задачи:
1. Запись на занятия (с проверкой абонементов)
2. Личный кабинет клиента (расписание, абонементы, история)
3. Система абонементов (активация, заморозка, списания)
4. Уведомления (email, Telegram)
5. Отмена записи клиентом и администратором
6. Листы ожидания на популярные занятия
7. Мобильная адаптация интерфейсов

### Результат:
- Клиенты могут записываться на занятия
- Автоматическое управление абонементами
- Система уведомлений

---

## Этап 5: Финансы и отчетность
**Цель:** Внедрить финансовый учет и расчет зарплат.

### Задачи:
1. Учет оплат (абонементы, разовые посещения)
2. Расчет зарплат тренеров (% от занятий)
3. Дашборды для администратора (выручка, посещаемость)
4. Отчеты (ежедневные, еженедельные, ежемесячные)
5. Экспорт отчетов в CSV/Excel
6. Статистика по направлениям и тренерам
7. Финансовая аналитика

### Результат:
- Полный финансовый учет
- Автоматический расчет зарплат
- Аналитические дашборды

---

## Этап 6: Тестирование, оптимизация и деплой
**Цель:** Подготовить проект к продакшену.

### Задачи:
1. Unit-тесты (Jest) для критической логики
2. E2E-тесты (Playwright) основных сценариев
3. Оптимизация запросов к БД
4. Настройка CI/CD пайплайнов
5. Финальная проверка безопасности
6. Документирование API и пользовательских сценариев
7. Подготовка к деплою на продакшен

### Результат:
- Протестированный и оптимизированный продукт
- Готовность к развертыванию
- Полная документация

---

## Технические требования к локальной разработке

### Минимальные требования:
- Docker Desktop или Docker Engine + Docker Compose
- Node.js 18+ LTS
- Git
- 4GB RAM минимум

### Команды для запуска:
```bash
# Запуск инфраструктуры (БД, Redis)
docker-compose up -d

# Запуск бэкенда (в режиме разработки)
npm run start:dev

# Запуск фронтенда (в режиме разработки)
npm run dev
```

### Проверка работоспособности:
- Бэкенд: `http://localhost:5000/api/health`
- Фронтенд: `http://localhost:3000`
- Swagger: `http://localhost:5000/api/docs`
- PostgreSQL: `localhost:5432`
- Redis: `localhost:6379`

---

## Критерии перехода между этапами
1. Весь функционал этапа работает локально
2. Покрыты основные happy-path сценарии
3. Код прошел ревью и закоммичен
4. Обновлена документация
5. Пользователь подтвердил работоспособность
