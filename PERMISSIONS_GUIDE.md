# Система управления правами пользователей

## Обзор

В системе реализована единая система управления правами через **роли пользователей**. Права доступа к календарю и к админке Django теперь синхронизированы и управляются из одного места.

## Как это работает

### 1. Роли пользователей

У каждого пользователя есть поле `Роль` с тремя возможными значениями:
- **Ученик (student)** - базовый доступ, только просмотр и запись на занятия
- **Модератор (moderator)** - расширенный доступ: создание, редактирование и удаление занятий, управление посещаемостью
- **Администратор (admin)** - полный доступ ко всем функциям системы

### 2. Группы Django

Автоматически создаются три группы Django, соответствующие ролям:
- **Student** - права на просмотр календаря и запись на занятия
- **Moderator** - права на управление занятиями и посещаемостью
- **Admin** - все права на модели приложения core

### 3. Синхронизация

При изменении роли пользователя в админке:
1. Автоматически назначается соответствующая группа Django
2. Старые группы удаляются
3. Пользователь получает все права из новой группы

## Управление правами

### Изменение прав для роли

Чтобы изменить права для определенной роли:

1. Перейдите в админку → **Группы**
2. Выберите нужную группу (Student, Moderator или Admin)
3. Отметьте/снимите галочки с нужных прав
4. Сохраните

**Важно:** После изменения прав группы они автоматически применятся ко всем пользователям в этой группе.

### Назначение прав пользователю

1. Перейдите в админку → **Клиенты**
2. Откройте нужного пользователя
3. В поле **Роль** выберите нужную роль
4. Сохраните

Группа и права обновятся автоматически!

## Текущие настройки прав

### Группа Student (4 права)
- Просмотр занятий (`view_classsession`)
- Просмотр записей (`view_booking`)
- Создание записей (`add_booking`)
- Редактирование своих записей (`change_booking`)

### Группа Moderator (10 прав)
- Все права Student +
- Создание занятий (`add_classsession`)
- Редактирование занятий (`change_classsession`)
- Удаление занятий (`delete_classsession`)
- Просмотр посещаемости (`view_attendance`)
- Управление посещаемостью (`add_attendance`, `change_attendance`)

### Группа Admin (48 прав)
- Все права на модели приложения core
- Полный доступ к управлению системой

## Решение проблем

### Пользователь не может создавать занятия

Проверьте:
1. Установлена ли роль `moderator` или `admin`
2. Присутствует ли соответствующая группа у пользователя
3. Есть ли у группы необходимые права

### Права не применяются

Попробуйте:
1. Пересохранить пользователя в админке
2. Проверить, что группа существует и имеет права
3. Выйти и зайти снова под пользователем

## Примечания

- Поле `user_permissions` скрыто из формы редактирования пользователя, так как права управляются через группы
- При создании нового пользователя ему автоматически назначается группа согласно выбранной роли
- Старая группа "Ученики" не используется и может быть удалена
