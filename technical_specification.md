# Техническое задание на разработку CRM-системы для йога-студии

## Общая информация о проекте

**Назначение:** CRM-система для управления йога-студией с полным циклом: от расписания занятий и управления залами до учёта посещаемости, финансов и личного кабинета ученика.

**Целевая аудитория:**
- Ученики йога-студии (запись на занятия, просмотр расписания, личный кабинет)
- Модераторы (управление расписанием, посещаемостью)
- Администраторы (полный доступ ко всем функциям системы)

# Страница 1: Регистрация (`/register/`)

## Назначение
Регистрация новых пользователей в системе по номеру телефона.

## Маршрут
- **URL:** `/register/`
- **Методы:** GET (отображение формы), POST (отправка данных)

## Ролевой доступ
- Доступна только неавторизованным пользователям
- Авторизованные пользователи перенаправляются на `/profile/`

## Функциональные требования

### Поля формы
| Поле | Тип | Обязательность | Валидация | Описание |
|------|-----|----------------|-----------|----------|
| first_name | text | Да | Макс. 150 символов | Имя пользователя |
| last_name | text | Да | Макс. 150 символов | Фамилия пользователя |
| phone | tel | Да | Формат +7 (XXX) XXX-XX-XX, уникальность в системе | Номер телефона (используется как логин) |
| password1 | password | Да | Мин. 8 символов, соответствие требованиям безопасности Django | Пароль |
| password2 | password | Да | Должен совпадать с password1 | Подтверждение пароля |

### Бизнес-логика
1. **Маска ввода телефона:** Автоматическое форматирование ввода в формат +7 (XXX) XXX-XX-XX
2. **Уникальность телефона:** Проверка на существование пользователя с таким телефоном
3. **Создание пользователя:** При успешной валидации создаётся запись в модели User с ролью 'student'
4. **Применение настроек по умолчанию:**
   - Назначение тарифов из UserDefaultSettings.default_tariffs
   - Добавление в группы из UserDefaultSettings.default_groups
   - Установка баланса из UserDefaultSettings.default_balance
5. **Автосоздание профиля:** После регистрации пользователь автоматически авторизуется и перенаправляется на `/profile/`

### Сообщения об ошибках
- "Пользователь с таким номером телефона уже существует"
- "Пароли не совпадают"
- "Неверный формат номера телефона"
- Ошибки валидации Django для каждого поля

### Элементы интерфейса
- Центрированная карточка формы на градиентном фоне
- Две колонки для полей имени и фамилии (flexbox)
- Поля расположены вертикально с отступами
- Кнопка отправки формы на всю ширину
- Ссылка на страницу входа внизу формы
- Индикаторы обязательных полей (*)
- Подсказки под полями (help_text)
- Блоки для отображения ошибок валидации

- Мобильная версия: поля имени и фамилии располагаются в одну колонку
- Планшетная версия: аналогично десктопу

## Технические требования

### Backend
- **Model:** User (AbstractUser)
- **Form:** RegistrationForm (Django Form)
- **View:** Function-based view с обработкой GET/POST
- **Template:** `core/register.html` extends `core/auth_base.html`

### Frontend
- **CSS:** auth.css (общие стили аутентификации)
- **JS:** phone-mask.js (маска ввода телефона)
- **Защита CSRF:** Обязательно для всех POST-запросов

### API эндпоинты
Не требуется (форма отправляется стандартным POST)

### Модель данных
```python
User:
- username (автогенерируется из phone)
- first_name (CharField, max_length=150)
- last_name (CharField, max_length=150)
- phone (CharField, max_length=20, unique)
- password (hashed CharField)
- role (CharField, default='student')
- balance (DecimalField, default=0)
- allowed_tariffs (ManyToMany to Tariff)
- groups (ManyToMany to Group)
```

# Страница 2: Вход в систему (`/login/`)

## Назначение
Авторизация зарегистрированных пользователей в системе.

## Маршрут
- **URL:** `/login/`
- **Методы:** GET (отображение формы), POST (отправка данных)

## Ролевой доступ
- Доступна только неавторизованным пользователям
- Доступна только обычным пользователям (role='student')
- Администраторы, модераторы и суперадмины перенаправляются на `/admin/login/`

## Функциональные требования

### Поля формы
| Поле | Тип | Обязательность | Описание |
|------|-----|----------------|----------|
| username | tel/text | Да | Номер телефона (логин) |
| password | password | Да | Пароль |

### Бизнес-логика
1. **Аутентификация:** Проверка учётных данных через Django authenticate()
2. **Проверка роли:**
   - Если пользователь имеет роль moderator/admin или is_superuser=True → редирект на `/admin/login/`
   - Если обычный пользователь → вход в систему и редирект на `/profile/`
3. **Создание сессии:** При успешной аутентификации создаётся сессия пользователя
4. **Обработка ошибок:** При неудачной попытке отображается сообщение об ошибке

### Дополнительные функции
- **Telegram Login Widget:** Кнопка быстрого входа через Telegram (опционально)
- **VK OAuth:** Кнопка быстрого входа через ВКонтакте (опционально)
- **Remember me:** Возможность сохранения сессии (стандартными средствами Django)

### Сообщения об ошибках
- "Неправильное имя пользователя или пароль"
- "Аккаунт деактивирован" (если is_active=False)
- "Доступ запрещён. Используйте вход для администратора" (для персонала)

# Страница 3: Личный кабинет (`/profile/`)

## Назначение
Отображение личной информации пользователя, истории посещений, предстоящих занятий и информации об абонементах.

## Маршрут
- **URL:** `/profile/`
- **Методы:** GET

## Ролевой доступ
- **Требуется авторизация:** Да
- Доступна всем авторизованным пользователям
- Для модераторов и администраторов отображается дополнительное боковое меню

## Функциональные требования

### Отображаемые данные

#### Шапка профиля
| Данные | Источник | Описание |
|--------|----------|----------|
| Приветствие | Вычисляется | "Доброе утро/день/вечер {Имя}" в зависимости от времени суток |
| ФИО | User.first_name, User.last_name | Полное имя пользователя |
| Телефон | User.phone | Номер телефона |
| Баланс | User.balance | Текущий баланс в рублях |
| Остаток абонемента | Subscription.sessions_remaining | Количество оставшихся занятий по активному абонементу |

#### Блок "Предстоящие занятия"
| Данные | Источник | Описание |
|--------|----------|----------|
| Дата | ClassSession.date_time | Дата занятия (дд.мм.гггг) |
| Время | ClassSession.date_time | Время начала (чч:мм) |
| Название занятия | ClassType.name | Тип занятия |
| Зал | Hall.name | Название зала |
| Цвет зала | Hall.color | Цветовая метка зала |
| Длительность | ClassSession.duration | Длительность в минутах |

**Критерии выборки:** Занятия с ClassSession.date_time > текущего времени, на которые у пользователя есть активная запись (Booking) со статусом 'confirmed' или 'paid'.

#### Блок "История посещений"
| Данные | Источник | Описание |
|--------|----------|----------|
| Дата | ClassSession.date_time | Дата прошедшего занятия |
| Время | ClassSession.date_time | Время начала |
| Название занятия | ClassType.name | Тип занятия |
| Зал | Hall.name | Название зала |
| Цвет зала | Hall.color | Цветовая метка |
| Длительность | ClassSession.duration | Длительность в минутах |

**Критерии выборки:** Занятия с ClassSession.date_time < текущего времени, которые пользователь посетил (Attendance.status = 'attended').

#### Боковое меню (только для модераторов/админов)
- Ссылка "Главная админа" → `/admin/`
- Ссылка "⚙️ Настройки новых пользователей" → `/admin/core/userdefaultsettings/`
- Ссылка "🔑 Группы прав" → `/admin/auth/group/`
- Ссылка "📅 Календарь" → `/calendar/`
- Ссылка "➕ Создать занятие" → открытие модального окна календаря

### Кнопки действий
- **"Перейти к расписанию"** (в шапке и внизу страницы) → `/calendar/`
- **"Выйти"** → `/logout/`

### Бизнес-логика
1. **Динамическое приветствие:**
   - 05:00–11:59 → "Доброе утро"
   - 12:00–17:59 → "Добрый день"
   - 18:00–04:59 → "Добрый вечер"
2. **Расчёт остатка абонемента:**
   - Поиск активного абонемента (Subscription) со статусом 'active'
   - sessions_remaining显示当前剩余次数
   - Если нет активного абонемента → "0 занятий"
3. **Фильтрация по ролям:** Боковое меню отображается только если user.is_moderator или user.is_admin

# Страница 4: Календарь занятий (`/calendar/`)

## Назначение
Центральный интерфейс для просмотра расписания занятий, записи на занятия и управления расписанием (для персонала).

## Маршрут
- **URL:** `/calendar/`
- **Методы:** GET

## Ролевой доступ
- **Требуется авторизация:** Да
- **Ученики:** Просмотр расписания, запись/отмена записи
- **Модераторы/Администраторы:** Полный CRUD операций с занятиями, управление посещаемостью

## Функциональные требования

### Режимы просмотра календаря
- **Месяц (dayGridMonth):** Отображение сетки месяца
- **Неделя (timeGridWeek):** Почасовая сетка недели
- **День (timeGridDay):** Почасовая сетка дня
- **Список (listMonth):** Список событий списком

### Отображение событий
| Параметр | Формат | Описание |
|----------|--------|----------|
| Заголовок | `{Время} {Название занятия} | {Зал}` | Например: "10:00 Растяжка | Дом йоги" |
| Цвет фона | Hall.color | Соответствует цвету зала |
| Время начала | ЧЧ:ММ | Локальное время |
| Длительность | Из ClassSession.duration | Визуальная длина события |

### Управление событиями (только модераторы/админы)

#### Создание занятия
**Способы инициирования:**
1. Клик по свободной ячейке календаря
2. Кнопка "Создать занятие" в навигации

**Поля формы создания:**
| Поле | Тип | Обязательность | Описание |
|------|-----|----------------|----------|
| Тип занятия | select | Да | Выбор из ClassType |
| Дата | date picker | Авто | Из выбранной ячейки календаря |
| Время начала | select (часы + минуты) | Да | Часы (08–20), минуты (00–50, шаг 10) |
| Длительность | number | Нет | По умолчанию из типа занятия |
| Зал | select | Нет | Выбор из Hall |
| Макс. участников | buttons + input | Нет | Кнопки 2–10 + произвольное значение |
| Повторять каждую неделю | checkbox | Нет | Генерация серии на 4 недели |

**Бизнес-логика:**
- При создании повторяющегося занятия генерируется 4 события с интервалом 7 дней
- Все события серии имеют общий recurrence_id (UUID)
- Проверка на конфликты времени для выбранного зала

#### Редактирование занятия
**Способы инициирования:**
1. Двойной клик по событию
2. Клик по событию → вкладка "Редактирование"

**Изменяемые поля:** Все поля как при создании

**Drag-and-Drop:**
- Перетаскивание события на другую дату/время
- Изменение длительности растягиванием
- Автоматическое сохранение изменений через API

#### Удаление занятия
**Для повторяющихся событий:** Модальное окно с выбором:
- "Удалить только это занятие" → удаляет одно событие
- "Удалить это и последующие" → удаляет событие и все следующие в серии (по дате)

### Запись на занятия (все пользователи)

#### Вкладка "Запись"
**Отображаемая информация:**
- Список записанных учеников (ФИО, телефон)
- Количество свободных мест (max_participants - количество записей)
- Статус записи текущего пользователя

**Действия для учеников:**
- **Записаться:** Кнопка активна если:
  - Есть свободные места
  - До начала занятия более 4 часов
  - Пользователь ещё не записан
- **Отменить запись:** Кнопка активна если:
  - Пользователь записан
  - До начала занятия более 4 часов

**Действия для модераторов/админов:**
- Просмотр полного списка записанных
- Ручное добавление клиента через поиск
- Отметка фактического посещения (чекбоксы)
- Сохранение посещаемости

### Поиск клиентов (для персонала)
- **Endpoint:** `/api/clients/search/`
- **Параметры:** query (строка поиска)
- **Поиск по:** first_name, last_name, phone
- **Возврат:** Список клиентов с ID, ФИО, телефоном

# Страница 5: Админ-панель Django (`/admin/`)

## Назначение
Полное CRUD управление всеми моделями системы, настройка прав доступа, конфигурация системы.

## Маршрут
- **URL:** `/admin/` и все вложенные пути
- **Методы:** GET, POST (стандартные Django Admin)

## Ролевой доступ
- **Суперадмины (is_superuser=True):** Полный доступ
- **Администраторы (role='admin'):** Полный доступ
- **Модераторы (role='moderator'):** Доступ к управлению расписанием, занятиями, посещаемостью
- **Ученики (role='student'):** Доступ запрещён (перенаправляются на `/profile/`)

## Функциональные требования

### Разделы админ-панели

#### 1. Тарифы (Tariff)
**CRUD операции:**
- Создание/редактирование тарифов
- Настройка параметров:
  - Название, тип (group/individual/split)
  - Цена за человека
  - Полная цена за сплит (авторасчёт)
  - Макс. участников
  - Параметры абонемента (доступность, кол-во занятий, стоимость, срок действия)

**Отображение в списке:**
- Название тарифа
- Тип
- Цена
- Статус активности
- Доступность абонемента

**Расширенная форма редактирования:**

# Интеграции

## Telegram Authorization

### Endpoint: `/api/auth/telegram/`
**Метод:** POST

**Требования:**
- Криптографическая проверка подписи данных (HMAC-SHA256)
- Валидация актуальности данных (не старше 24 часов)
- Автоматическая регистрация при первом входе
- Привязка telegram_id к пользователю

**Настройка:**
- TELEGRAM_BOT_TOKEN в .env
- TELEGRAM_BOT_USERNAME в .env
- Подробная инструкция в TELEGRAM_AUTH_SETUP.md

## VK Authorization

### Endpoint: `/api/auth/vk/`
**Метод:** POST

**Требования:**
- Проверка OAuth токена
- Валидация данных пользователя
- Автоматическая регистрация при первом входе
- Привязка vk_id к пользователю

**Настройка:**
- VK_SERVICE_KEY в .env
- VK_CLIENT_ID в .env
- App ID в JS-коде

- Изменения в группе синхронизируются со всеми участниками

**Стандартные права по моделям:**
- add_{model} — создание записей
- change_{model} — редактирование
- delete_{model} — удаление
- view_{model} — просмотр

# Бизнес-правила

## Правило 4 часов
- Запись на занятие возможна не позднее чем за 4 часа до начала
- Отмена записи возможна не позднее чем за 4 часа до начала
- Дедлайн оплаты устанавливается за 4 часа до занятия

## Ценообразование для сплита
- Если в сплит-группе 2 человека → цена делится поровну
- Если в сплит-группе 1 человек → платит полную стоимость за двоих

## Абонементы
- Активация при первом использовании
- Срок действия отсчитывается от даты активации
- Сгорание неиспользованных занятий по истечении срока
- Не для всех тарифов доступны (настраивается)

## Повторяющиеся занятия
- При создании с флагом is_recurring генерируется серия на 4 недели вперёд
- Все события серии имеют общий recurrence_id
- Удаление серии: выборочно (одно событие) или все последующие
